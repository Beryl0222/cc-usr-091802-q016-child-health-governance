# 儿童健康结论治理

面向儿童可穿戴设备健康结论的**可问责治理服务**。它解决的核心问题是：设备给出的每一条健康结论，都必须能回答"依据哪条规则、规则由谁批准、是否在有效期内、数据从哪里来、为什么这样判断、被谁修订过"；回答不了时，**停止给结论**，而不是给一个羞辱性标签。

典型事故对照：身高 167 cm、体重 50.5 kg 的女孩 BMI≈18.1，本在正常范围。旧系统把她标为"偏重"，客服却说不出适用年龄和算法版本，也无法还原设备当时上报的数据。本服务从机制上让这种结论无法产生。

## 治理原则（在代码中强制，而非靠人工自觉）

1. **只有已会签且在有效期内的规则可被采用。** 医学、隐私、文案三个角色缺一不可；每条批准绑定规则内容的 SHA-256 指纹，批准后任何改动都会让批准失配。
2. **证据不足即中性回退。** 单位不支持、校准后越界、姿态与年龄不符、身高体重测量时间跨度过大、设备时钟不可信、没有适用规则——任一不满足，结论只能是"证据不足"，建议重新测量或咨询专业人员。
3. **不诊断、不羞辱、不带货。** 结论分类只有"在参考范围内 / 建议结合趋势关注 / 证据不足"；文案入库前过红线检查（确诊、肥胖、"你太胖"、付费/购买/减肥课、羞辱性表达一律拒绝）。
4. **算法灰度必须监护人明确同意，且随时可退出。** 灰度规则对未同意者不可见；退出立即用正式规则重评全部受影响记录。开启需 `confirm=true` 的显式确认。
5. **按采集时点选规则。** 离线补传以设备记录的采集时间选择当时有效的规则（受 30 天补传窗口约束，时钟不可信则回退）；规则不追溯，也不提前适用。
6. **修订即新版本，旧结果立即下架并通知家庭。** 单位修正、生日修正、规则撤回、退出灰度都会产生新版本；旧版本置为 `superseded`/`withheld`，不再向家庭展示，并生成家庭通知。
7. **家长可读懂每次判断。** 记录视图包含：数据来源（型号、原始读数、校准值、时钟来源）、适用范围（年龄区间及生日依据、性别分组、规则版本与指纹、参考区间、生效窗口）、判断理由、完整修订链。
8. **产品团队只能看到 k-匿名字段统计。** 任何分组人数 < 50 一律抑制（含互补抑制，不能用总数反推小群体）；仅允许按白名单维度分组，person_id、record_id、生日、原始读数永不进入统计。

## 架构

```
governance/
  models.py       领域核心：时间、指纹、三方会签、安全文案红线、设备/儿童模型
  calibration.py  单位换算(SI)、设备校准(测量类型×姿态×采集方式)、姿态政策、BMI 可信度
  rules.py        规则库：会签校验、有效期、内容指纹、撤回、灰度选择
  engine.py       评估引擎：校准→可信度→选规则→可解释结论；中性兜底
  service.py      编排：同意、记录、结论版本链、修订触发、通知、家长视图
  stats.py        k-匿名质量统计（最小群体门槛 + 维度白名单）
  app.py          装配：种子设备/规则目录、审计、JSON 持久化
  api.py          标准库 HTTP API（Bearer 令牌、监护人/产品/admin 角色边界）
service.py        启动入口（--check 自检 / --data 持久化）
tests/            58 个测试：事故回归、会签篡改、灰度、补传、修订、统计、HTTP、持久化
```

所有结论依赖只由**服务侧**持有：设备端只能上报原始读数与单位，无法自带校准、自带阈值或自带年龄。年龄依据监护人维护的生日按采集日计算。

## 运行

```bash
python3 service.py --check                      # 装配自检：会签/指纹/红线/设备目录
python3 service.py --port 8000 --data data/state.json
python3 -m pytest -q                            # 或 python3 -m unittest discover -s tests
```

启动后 `GET /health` 返回服务标识。

## API 速览

鉴权：`Authorization: Bearer <token>`。角色：`guardian`（绑定单一儿童）、`product`（仅聚合统计）、`admin`（建档、规则撤回）。

> `POST /v1/bootstrap-token` 仅为演示/测试引导发证；生产必须替换为带监护关系核验的认证。

| 方法 | 路径 | 角色 | 说明 |
|---|---|---|---|
| POST | `/v1/persons` | guardian/admin | 建档（person_id、生日、性别） |
| POST | `/v1/measurements` | 监护人(本人) | 提交测量；支持 `backfill`+`collected_at` |
| GET | `/v1/records/{id}` | 监护人(本人) | 家长可读的完整解释与修订链 |
| POST | `/v1/records/{id}/correct-units` | 监护人(本人) | 单位/读数修正 → 新版本 |
| POST | `/v1/persons/{id}/correct-birth-date` | 监护人(本人) | 生日修正 → 全部相关记录重评 |
| POST | `/v1/canary-consent` | 监护人(本人) | 灰度开关（需 `confirm:true`） |
| GET | `/v1/persons/{id}/notifications` | 监护人(本人) | 首条/修订/撤回通知 |
| POST | `/v1/rules/{id}/withdraw` | admin | 撤回规则并重评、通知受影响家庭 |
| GET | `/v1/rules` | 已认证 | 规则清单（会签角色、指纹、生效窗口） |
| GET | `/v1/quality?group_by=model_id,verdict` | product/admin | k-匿名质量统计 |

### 提交示例

```json
{
  "person_id": "mei",
  "model_id": "watch-k1",
  "readings": [
    {"measurement": "height", "value": 167, "unit": "cm", "posture": "standing", "capture_mode": "manual"},
    {"measurement": "weight", "value": 50.5, "unit": "kg", "posture": "standing", "capture_mode": "manual"}
  ]
}
```

支持单位：身高 `cm/m/inch`，体重 `kg/g/lb/jin`。结论中的参考区间、规则版本与指纹、校准后数值全部回显。

## 规则目录治理

- 新规则 = 新 `rule_id`（同 id 不可覆盖）；阈值、文案、适用年龄/性别/型号、生效窗口任一变化都会改变内容指纹。
- 规则上线前必须收齐医学、隐私、文案三条批准，且批准时间不晚于生效时间。
- 撤回立即、永久生效（对历史补传也生效）；被撤回规则引用的在展结论全部重评，无替代已会签规则时直接 withhold 为"证据不足"。
- `governance/app.py` 中的种子规则阈值为**演示值**，上线前必须由真实医学负责人替换并重新走会签。

## 边界与未覆盖项（生产化待办）

- 持久化为单机 JSON、令牌不落盘；生产应换为数据库存储与带监护关系核验的身份系统。
- 通知仅入队（`delivered` 标记），未接推送通道。
- 规则管理后台（上传规则、收集三方批准）未提供 UI，目前经装配代码加载。
- 统计阈值固定 50，互补抑制策略已内置，但差分隐私等增强未实现。

`fixtures/sample.json` 仅保存可公开的字段与示例，不含任何真实个人资料或业务凭据。
